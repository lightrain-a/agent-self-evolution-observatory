## 4. Former candidate: Counterfactual Branch Residual Gating (CBRG) — current extension STOP/MERGE

For one byte-identical trajectory `tau`, generate both released counterfactual reflections:

`M_S = W_S(tau)`

`M_F = W_F(tau)`

Factorize:

`C(tau) = Core(M_S, M_F)`

`D_S, D_F = Residual(M_S, M_F)`

where:

- `C` is the branch-invariant actionable/procedural core;
- `D_S / D_F` are semantic claims/rules introduced specifically by the reward branch.

For target query/state `o` and evidence metadata `z_r`, expose:

`M_r(tau;o) = C(tau) + g(o, D_r, z_r) * D_r`.

The core remains available. Only the reward-branch residual receives conditional actionable authority.

### What may be novel

Not core/residual factorization. Not provenance. Not applicability routing.

The narrow candidate residual that entered D0 was:

> **the semantic residual created by counterfactual success/failure reflection of the same byte-identical trajectory, together with outcome-independent evidence-gated trigger authority over only that residual.**

Generic `Core/Residual`, neutral/metadata memory, and semantic applicability are measurement/control interfaces only. They are not allowed to re-enter the novelty set by being composed into a larger router.

This current extension is now STOP/MERGE for an earlier gate reason: the required outcome-independent semantic-validity layer cannot be qualified from the frozen zero-call evidence set. The definition is retained only as lineage and a possible future reopen target under the explicit reopen contract.

## 5. Why each component exists

### Counterfactual pair

Needed because C1's strongest finding is a label-only write intervention. A single observed branch cannot identify which actionable statements are reward-branch-specific.

### Core/residual compiler

Needed to prevent one potentially wrong reward bit from rewriting branch-invariant procedure. Plain factorization is a baseline; it becomes useful here only as the measurement interface for the label-induced residual.

### Residual evidence authority — the surviving nonbaseline component

The reward label itself is not evidence for a residual claim. Each branch residual must bind to outcome-independent source/trajectory facts and receive a claim-level status such as supported / contradicted / unverifiable. This evidence-validity signal must add information beyond neutral/metadata, generic factorization, and semantic applicability baselines.

### Target-state applicability — baseline/eligibility only

Needed because native branch effects are sparse even after retrieval. Applicability may decide whether a residual is relevant enough to inspect, but **semantic relevance alone cannot grant branch-specific actionable authority**. High relevance plus contradicted/unverifiable evidence must not be treated as a valid trigger.

Every component is removable. If neutral core, always-on factorization, or a simple similarity rule ties the full method, remove/stop the complex method.
