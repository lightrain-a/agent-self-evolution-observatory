\section{Controlled Skill Intervention}
\label{sec:intervention}
The experiment treats a skill as an intervention on the computation available to an agent. The primary question is local: does the procedure associated with a failure improve the same endpoint beyond a matched reusable control?

\subsection{Freeze the endpoint before changing the skill}
Each endpoint is fixed before arm outcomes are generated. Its benchmark record identifies the requested analytical operation. The same record supplies a deterministic finding verifier. For executable probes, the visible CSV must match its recorded SHA-256. The benchmark reference procedure must also run successfully in an isolated qualification environment. A failed candidate remains in the audit trail and is never replaced after outcomes begin.

\subsection{Hide the implementation behind one interface}
The executable arms expose the same native tool definition:
\begin{quote}
\texttt{persistent\_skill(): Execute the registered reusable analysis procedure for the current task when it is useful.}
\end{quote}
The function name is shared across arms. Its description is shared as well. The JSON argument schema is identical. The model therefore chooses whether to call the tool without seeing which implementation is registered.

When the targeted tool is called, the runner executes the benchmark-recorded procedure on the hash-verified visible data. The original matched control executes neutral schema work through the same tool surface. Its returned text has the same word count as the targeted result. The no-skill arm exposes no additional tool.

The model receives the frozen dialogue through the current user turn. It may answer immediately or issue one native tool call. After the tool returns, the model produces the final answer. A second tool call is a protocol failure. We report tool invocation separately from task success so that an implementation effect cannot be confused with different call rates.

\subsection{Measure the downstream endpoint}
The final response is scored with the benchmark verifier that existed before our intervention. Keyword endpoints use the frozen benchmark phrases after deterministic normalization. Numerical endpoints require a response value inside the frozen benchmark range. The scorer never receives an arm label.

Let $Y_i^T$ denote success for endpoint $i$ under the targeted implementation. Let $Y_i^G$ denote success under the matched control. The paired effect is
\begin{equation}
\widehat{\Delta}_{T-G}=\frac{1}{n}\sum_i (Y_i^T-Y_i^G).
\end{equation}
The primary test is an exact one-sided paired McNemar/binomial test over discordant endpoints. The preregistered gate requires $\widehat{\Delta}_{T-G}\geq0.20$. It also requires $p\leq0.05$. Targeted versus no skill is secondary. After execution begins, endpoint membership is fixed. The threshold is fixed as well. Repeated seeds on the same endpoints are not used to alter the primary decision.

\subsection{A stronger control for procedure specificity}
Neutral schema work controls the visible tool interface, yet it leaves a second question: perhaps any substantive analysis would help. We therefore add F6 as a stronger post-hoc diagnostic. F6 reuses the exact F3 targeted initial response for every endpoint. This preserves the model's original decision about whether to call \texttt{persistent\_skill}. No new initial model call is made.

For each endpoint, the alternative implementation is another benchmark-recorded analytical procedure from the same TimeSage-MT task. The procedure must execute on the same hash-pinned CSV. Selection is deterministic before F6 continuations: the nearest different procedure in dialogue order is used. Its tool output is matched to the targeted output length. Verifier overlap is recorded and never used for selecting the control.

This diagnostic changes the estimand from \emph{correct procedure versus neutral tool work} to \emph{correct procedure versus another substantive procedure}. Because F6 was designed after observing F3, it has identification value without primary-claim closure authority.

\subsection{From local executable value to persistent state}
The TimeSage-MT probes test whether the hidden implementation matters at a frozen endpoint. TimeSage-EV supplies the stronger temporal object. There, a skill must be written before a later release. Its implementation remains fixed when later endpoints arrive. C4 asks whether this state continues to help after the evidence changes. This chronological experiment is distinct from the local implementation swap evaluated here.
