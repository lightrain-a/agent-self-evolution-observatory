# 科研专题与综述：洞见先行、证据就近

更新：2026-10-29。适用于 RSI 网站章节、论文精读和综述回填；不替代原始来源核验。

完整个人方法论已保存到 Obsidian：`30-Workflows/科研论文/从零到论文/26-科研专题与综述网站-洞见先行和证据就近的可读性方法.md`，并从既有总入口与“读者逻辑优先”笔记链接。本文件供网站维护者和后续综述写作任务直接读取。

## 从四轮修改得到的规则

1. 资料完整不等于讲清楚。不要把内部分类、I编号和长表直接作为阅读主线。
2. 具体例子解释术语，但开场先给3–6条有证据的洞见，说明哪些指标未必同向变化。
3. 权衡不是必然的零和。说明适用条件，并允许一种更好的干预同时改善多个指标。
4. 每个核心小节就近介绍代表论文；末尾只保留索引与细节，不让读者倒查全部证据。
5. 原文观察、机制解释、跨领域迁移、LLM提案、RSI元决策分别标明。没有训练或独立验证时，不写成结果。
6. 正文以问题和具体动作组织；公式、完整统计及宽矩阵按需展开。关键事实边界不可全部隐藏。
7. 网站可以帮助论文改善论证，但回填仍需回查原文，不用自写网站给自写论文“作证”。

## 一条 Insight 的最小单元

**在什么条件下 → 哪个指标变好 → 哪个结果未必变好 → 证据在哪里 → 什么处理有可能改善二者。**

例如“更多采样覆盖了更多解法”必须接着区别：单次正确率、候选中至少有一个正确、最终选择器选中正确，以及真实更新后是否持续变好。不能只写“探索更高效”。

每节建议顺序：

> 具体读者问题 → 原论文观察与操作 → 机制解释及边界 → 已有办法 → LLM可检验处理 → RSI是否能学会选择 → 联合指标与完整成本。

这里的LLM/RSI方案是研究提案，不是每节都强行发明一个新算法。若原方法已经解决问题，应明确承认。

## 论文进入小节的方式

每篇论文只承担一种明确作用：现象、机制、可用方法、强基线或反例。小节开始或论点之后就出现论文名称与来源，不只给一个编号。

推荐：“Self-Instruct扩展有哪些题，STaR为已有题补推理轨迹。两者都增加样本，但操作对象不同；比较时固定其中一个分布。”

不推荐：“经验获取包括任务构建、交互探索、多样性维护和信号资源配置”，然后末尾再堆十篇论文。

## 可读性和严谨性一起验收

- 第一屏能复述本章的几个具体发现，而不必先背四功能和I编号。
- 每个核心小节至少有就近的原始文献，原文对象和干预清楚。
- 例子明确标为解释性例子；猜测机制不写成神经测量结果。
- 不把跨领域现象直接称为已完成的LLM/RSI结果。
- 所有成本注明省的是生成、验证、标注还是训练。
- 电脑和390px手机都能点击小节、打开折叠且没有横向页面溢出。
- 修改唯一源，保留网址、旧锚点、I编号和分类；保存并发任务已有修改。
- 本地构建、Git提交、推送和线上部署是不同状态，分别核验与报告。
