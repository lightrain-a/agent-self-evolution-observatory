I1：脚手架学习法——哪些该自己学会，哪些用时再查？

采不采得到吸收了会不会丢

一句话：调试思路最好自己掌握，但经常变化的 API 规则可以用时再查。Agent 能自己判断哪些该学会、哪些该留作外部帮助吗？

Challenge （难在哪里）

在帮助下完成任务，不等于撤掉帮助后还能独立做。什么都写进 Skill，可能把过时规则也记住；什么都留在外部，又要反复查询。难的是还不知道未来任务怎么变，就要先决定哪些知识值得长期掌握。

现有工作 （别人研究了什么）

R²Orch 研究的是怎样把 Skill 内化、什么时候可以撤掉 Skill；PATS 研究的是随着学习进展怎样调整并撤除临时支架。我们不是再做一次“帮助逐渐减少”，而是研究不同经验究竟该留在哪里。[S26][S27]

Insight （为何可解）

外部帮助并不都一样。稳定且反复使用的操作方法可能适合自己学会；容易变化的事实可能更适合按需查询。比较撤除帮助后的独立能力、知识变化频率和长期成本，有机会学会这两种方式的取舍。

Design （如何做）

将辅助经验分成稳定方法、易变规则和临时提示，让 Agent 选择内化、外置查询或混合保留。分开测“完全不给帮助”和“允许按需查询”的表现，再根据这些结果更新下一轮的选择方式。

拆分辅助经验稳定方法 / 易变知识
选择存放方式内化 / 查询 / 混合
新任务测能力撤辅与查询分开
更新取舍规则比较收益和成本

实验设计 （怎么验证）

准备稳定的调试技巧与会变动的 API 规则，在相同预算下比较全部内化、全部外置、固定渐隐、自适应取舍，并与 R²Orch/PATS 的可复现做法比较。重点看无辅助的新任务成功率、API 更新后的适应性、调用成本和旧能力退化。如果固定规则同样好，说明动态选择还没有额外价值。

I2：因材施教——同样犯错，为什么学习方法不同？

信号对不对采不采得到

一句话：两个 Agent 都不会修一个 Bug，一个看示范就会了，另一个要比较几次失败才学得会。怎样找到各自最适合的学习方法？

Challenge （难在哪里）

知道“错在哪里”，不等于知道“怎么学最快”。同一种错误，换个模型或学习阶段，最有用的学习方式可能不同；但把所有学法试一遍又太贵。还要避免把眼前这道题的进步当成长久的能力提升。

现有工作 （别人研究了什么）

RSIFlow 研究的是失败后该修改模型、Harness 还是任务产物；MetaSkill-Evolve 研究的是任务 Skill 和改进 Skill 的方法怎样一起演化。我们先固定更新的是 Skill，只研究同样的失败该用哪种学习方法，而不是重新做更新对象路由。[S28][S06]

Insight （为何可解）

只看错误标签，可能看不出 Agent 最适合的学法；但是少量“试学”能告诉我们，它看示范、做反例对照或自己重试后，哪一种真的学得更快。Agent 变强后重新测，就能发现原来有效的方式是否还适合。

Design （如何做）

对同一种失败，从相同 Skill 快照出发，分叉尝试示范、对比失败和独立练习。用另一批任务检验每种方式学完后的独立能力，再选择下一轮学法，并记录它在不同能力阶段的效果。

固定同类失败同一个 Skill 更新目标
小预算试学示范 / 反例 / 重试
测独立进步测试任务不能参与试学
下轮重新选随能力更新学法

实验设计 （怎么验证）

选多个能力阶段的 Agent，在同类任务上比较固定学法、只按错误类型选、普通 bandit、根据少量试学反应选。试学本身的费用也计入预算；主要看未见题的独立提升，以及能力变强后最佳学法是否改变。与 I6 分开：I2 只决定当前学习任务该怎么学，不决定跨多轮要转去补知识还是改验证器。

I3：温故知新——新方法有用，却和旧方法冲突怎么办？

吸收了会不会丢安全

一句话：Agent 学会一个更快的新方法，却把以前在另一种场景下正确的做法弄坏了。新旧本事能不能都留下来？

Challenge （难在哪里）

新 Skill 确实提高了部分任务的成功率，却可能让旧任务变差。直接回滚就失去了新进步；把所有旧题重做一遍又浪费预算。首先得弄清是旧知识真忘了，还是新旧规则用错了地方。

现有工作 （别人研究了什么）

HCL 研究的是 Harness 更新后如何兼顾新任务与旧任务；SkillBoost 研究的是用回归检查和约束防止新 Skill 伤害旧能力。我们进一步研究当新旧方法都各有用处时，怎样通过复习修好冲突，而不是只能拒绝新更新。[S29][S30]

Insight （为何可解）

有些退化未必是忘记，而是两个原本都有效的方法，被用在了不适合的场景。只要找到“什么时候用旧规则、什么时候用新规则”的区别，少量针对这些边界的练习，可能比全部重放旧经验更有效。

Design （如何做）

比较修改前后的失败轨迹，找到出现冲突的条件，自动生成少量只改变一个关键条件的练习。用这些例子修订 Skill 的适用范围或选择规则，必要时再对参数做巩固。最终既要会用新方法，也不能丢旧能力。

发现旧任务退化新旧版本对比
定位冲突条件何时该用哪一条
有针对性地复习只练容易混淆的场景
一起检验新旧能力旧题 / 新题 / 组合题

实验设计 （怎么验证）

准备两套分别有效、合起来容易冲突的 Skill，并加入自然学习中出现的冲突案例。比较退化即回滚、均匀重放、MIR 风格重放、针对冲突条件复习；固定复习次数和记忆预算。分别测旧能力保持、新能力增益、组合任务成功率。如果优势只来自存了更多规则或多练了题，就不能归因于我们的复习方法。[M09]

I4：生产性失败——失败一次就总结，还是再试几次？

信号对不对有没有新东西采不采得到

一句话：API 超时一次，Agent 就总结“这个工具以后别用”，可能学错。什么时候应该继续试，什么时候才值得把经验写进 Skill？

Challenge （难在哪里）

一次失败可能是策略错了，也可能只是网络偶尔超时。太早总结，会把偶然现象当成通用规律；继续试太久，又会浪费探索预算。RSI 不一定有人告诉它正确做法，需要它自己根据执行反馈辨别原因。

现有工作 （别人研究了什么）

ActiveSaddler 研究的是哪些失败模式更值得继续训练；Trace2Skill 研究的是怎样从多条执行轨迹提炼可复用 Skill。我们研究的是面对这一次失败，下一步试什么，什么时候证据够了可以开始总结。[S16][S31]

Insight （为何可解）

不同失败原因，往往会对下一次尝试给出不同预测。一次只改变一个关键条件，就有可能排除错误解释。当继续探索已经很难提供新信息时，再停止并总结经验。关键不是失败越多越好，而是每次尝试能否帮助弄清原因。

Design （如何做）

失败后先列出两三个可能原因，选择最能把它们区分开的安全小实验，例如同样条件重试或只改变一个 API 参数。持续记录支持和反对各原因的证据，足够确定再更新 Skill；证据不够时允许暂不总结。所有试验只在受控环境运行。

列出失败原因策略错 / 工具故障 / 偶发
做辨别性尝试只变一个关键条件
判断何时停止证据是否足够
形成新 Skill再到未见任务复验

实验设计 （怎么验证）

在 API 异常、工具使用和代码执行任务上，比较失败后立即总结、固定重试 N 次、随机补充尝试、针对可能原因选试验并决定停止。匹配 Token、环境调用和总预算，混合可控故障与自然失败。主要比较写入错误规则的比例、未见场景的迁移、单位成本的学习收益；不把“多试几次自然多成功”误当成新机制。整个过程不需要外部教师告诉标准答案。

I5：十模型互教——什么时候交换舞伴，才能一起变强？

有没有新东西采不采得到吸收了会不会丢

一句话：十个模型各自持续更新。我们不仅问谁更强，而是问谁教的东西我现在学得进、继续交流还有多少收益、何时换人才能共同成长。

Challenge （难在哪里）

伙伴帮我答对，不等于自己学会；学完涨分，也可能只是同样预算自己练就能取得的进步。双方能力和已学知识不断变化，原先最好的搭档可能变得重复；换伴顺序的收益还可能只是普通课程效应。

现有工作 （别人研究了什么）

CORY 已联合训练两个模型并交换角色；PopuLoRA 已做 LoRA 群体自博弈；OPCoD 已用同伴反馈进行双向自蒸馏；CERA-MoA 已联合更新路由与 Agent；HACE 已做异构互惠学习。动态伙伴选择也已有 AAMAS 2026 SE Workshop 前作，不能写成主会或首次提出。[S200][S32][S33][S202][S90][S201]

此前的 MACE 伙伴探索和 Nature 交流顺序研究继续作为相邻证据；它们不直接证明十模型权重学习收益。[S34][E90]

Insight （为何可解）

伙伴的价值应由双方撤伴后的表现，减去同预算自学后的表现衡量。对方独有的知识、我当前的可吸收性和过去接触过的内容，可能共同解释为何该留伴或换伴；这是待检验关系，不是固定强弱排名。

Design （如何做）

固定 OPCoD 式 LoRA 自蒸馏和反馈门控，正常每轮五对、双向教学。小规模受控试学得到有方向净增益；用同容量的带/不带历史收益预测器在十节点图中选配对，按边际收益与不确定性决定持续多久。缺乏可信增益时允许同预算自学。所有试探和回退成本计入总预算。

独立十模型五规模 × 数学/代码
固定互教更新只改变伙伴关系
相对自学测收益撤伴、新题、保持
继续或重配历史、预算与置信度

实验设计 （怎么验证）

先做四模型 6 配对，再开展十模型实验；比较固定伙伴、随机、round-robin、能力匹配、即时收益和独立净增益。顺序实验同时固定边集合、接触次数和预算，并加入相同材料重排、冻结教师、双方共同更新三层控制。主指标为个人独立能力、群体学习效率、旧能力保持与验证过的技能覆盖，不是投票成绩。

I5只研究谁与谁学、持续多久和伙伴顺序；不改变 I2 学法、I3 巩固、I6 轨迹、I7 先试/先学、I8 错误选择。完整方法、最近邻、公式和实验契约；历史教学反馈支线仍在唯一 I5 页面内。

I6：失败学习价值——同样答错，哪条失败更值得学习？

信号对不对有没有新东西采不采得到

一句话：同一个模型解同一道积分题，两次都给出相同的错误答案：一次直接套错公式，一次尝试了几个正确步骤却仍答错。用哪一次失败来学习，才能让以后更多新题做对？又该在什么时候停止重试、改天再学？

Challenge （难在哪里）

只看最终答案，两条失败都是零分；但错误过程中有没有正确子步骤、有没有暴露新原因，可能决定这次纠错能学到什么。失败轨迹更长、看起来更接近答案，也未必更值得训练。如果同一道题已连续失败，继续采样可能浪费预算；可现在学不会，不代表补过基础后仍学不会。

现有工作 （别人研究了什么）

Learn from Failure 研究如何利用失败的定理证明轨迹；SOAR 根据学生实际进步生成值得学习的新题；BEACON 研究推理时何时停止继续采样；Region of Proximal Learning 研究人类何时离开当前学习材料。我们研究的是同题同样答错时，哪条失败过程在固定纠错后更能提高未来独立能力，以及何时停止收集这种失败，不是更换教学方式或提高当前 pass@k。[S47][S48][E16]

Insight （为何可解）

失败过程比最终对错多提供一层信息：模型已经走对了哪几步、在哪个规则上反复走错、下一次失败是否仍会暴露新缺口。从相同模型出发，用相同正确反馈分别纠正不同失败，再比较未见题的独立进步，就可以为每条失败估计真实学习价值。如果新失败已很难增加收益，就应比较纠正已有失败、换题或暂缓后重访。

Design （如何做）

从同一模型检查点在同一道题上采集多条自然失败，尽量匹配最终错误、轨迹长度与反馈信息；随机指定其中一条作为学习材料。固定正确答案、教学顺序、更新器和训练预算，分叉更新并在撤掉提示后测新题。先用真实迁移增益给失败定价，再训练只看纠错前信息的轻量预测器；比较继续收集、纠正已有、换题、暂缓重访的下一次投入。

同题收集不同失败同版模型，结果尽量一致
固定纠错方法同反馈、同 LoRA/Skill 预算
新题独立后测迁移、旧能力回归、成本
选失败与停止时机继续 / 换题 / 暂缓重访

实验设计 （怎么验证）

先做同题配对实验，比较只看正确解法、随机失败、最长失败、最接近正确的失败、按置信度选、预测学习增益选；模型快照、教师反馈和总 token/FLOPs 匹配。报告无提示未见题提升、旧能力损失与失败价值的跨题稳定性。再比较固定重试 K 次、简单学习进展阈值、收益驱动停止/暂缓，并事先约定重访条件。如果差异只来自更长轨迹或更多训练，或早停没超过简单阈值，就缩小主张，不另加复杂停止模块。[M12][S45]

正交边界：I6 固定先试还是先学（交给 I7）和纠错规则类型（交给 I8），只研究失败中间过程的增量价值与是否继续投入。查看同题配对、停学与重访的完整实验 →

I7：学习顺序——先看例题，还是先独立尝试？

采不采得到吸收了会不会丢

一句话：学同一道多步骤数学题，模型 A 先看完整解法再练习，模型 B 先独立尝试、失败后再看同一解法。学完撤掉例题，谁更会解新题？这种优势会不会随着模型变强而反过来？

Challenge （难在哪里）

看过示范后立即答对，可能只是照着步骤模仿；先做再学的提升，也可能只是比另一组多练了一次。更难的是，两种顺序可能让模型探索到不同的正确解题路径，而当前分数却差不多。只比较一次做题正确率，无法判断模型有没有在后续更新中真正学会、是否丢掉了原有的解法。

现有工作 （别人研究了什么）

Sinha & Kapur（2021） 汇总 53 项人类教育研究，发现某些概念知识和迁移任务中“先解题后教学”有优势，但程序性知识未显示同样的总体差异；Najar 等（2015） 已研究按学生状态选择示范或练习；He 等（2025） 还观察到不同人群的顺序优势可能相反。我们不是首次比较教学顺序，而是研究 LLM 经过相同预算的持久更新后，独立解题能力、可采样的正确解法和多轮迁移如何受顺序影响。

Insight （为何可解）

两组都能看到同一份正确示范，但先试的人在看到答案前，已经走过自己的候选路径；先看的人可能更快掌握标准步骤，却可能更依赖示范。这两种影响不能靠眼前一道题判断。只改变学习先后，撤掉教师和临时上下文后再测新题，就能判断顺序究竟改变了独立能力，还是只改变了即时模仿。

Design （如何做）

在同一个模型检查点、同一组题目上随机分成两支：A 先看示范再练习，B 先独立尝试再看相同示范。控制示范内容、尝试次数、采样配置、教师调用、训练 token 和 LoRA/Skill 更新步数。更新完清空示范上下文，在未见题上独立测试。只有先证明不同任务或模型阶段的最佳顺序确实会变化，才考虑用先前历史训练顺序选择器。

同一检查点分两组教师、题目、预算一致
只交换先后次序先学再做 / 先做再学
撤掉示范独立考试新题正确率与正确解法
多轮更新后复测顺序优势是否改变

实验设计 （怎么验证）

先选一类多步骤数学题，比较固定先学、固定先试、匹配次数的额外练习、无示范基线；后续只有在发现稳定顺序异质性时，才增加按历史能力选择和 contextual bandit 对照。用同预算的无提示 pass@1、固定 k 下的 pass@k、不同且正确的解法数量、旧能力保持及跨多轮更新的迁移作为指标。按知识点聚类统计，不按同题多次采样扩大样本量。如果优势只是练习次数更多或无效答案更多，就不能说顺序提高了探索与自我改进。

正交边界：I7 只改变尝试与示范的顺序；I6 在顺序固定时选择哪条失败过程，I8 在纠错方式固定时研究哪类错误有跨题迁移价值。查看人类教学的前作边界、两顺序协议与长期对照 →

I8：错误学习迁移——为什么改正一种错误能学会一类题？

信号对不对吸收了会不会丢安全

一句话：两个模型都把一道积分题做错。一个看完正确答案只会重做原题；另一个却学会同一公式，连几十道新题也能做。纠正哪个错误更可能举一反三？能否在真正训练前判断？

Challenge （难在哪里）

模型很自信地答错，不代表它缺的知识少，也不代表纠正后进步一定大。当前题答对、同模板变体答对、真正掌握一条规则是不同的结果。每个错题都完整训练一遍才能知道收益，成本太高；直接按难度、置信度或损失排序，又可能选中只会记住答案、却不会迁移的错误。

现有工作 （别人研究了什么）

Hypercorrection 与 Nature Communications 2018 的人类学习研究发现，已有信念与可信反馈的冲突可能影响纠错记忆，但不等于 LLM 已能跨题学习。Self-Error-Instruct 已按模型错误类型生成并筛选训练数据；LESS 和 DATAPROPHET 已研究训练前预测数据价值；RULE-EDIT 已区分规则文本修复与实例迁移。我们研究的是这个模型当前犯的某个错误，在固定纠错预算后究竟能让多少未见同规则题变好，而不是首次使用错题或首次预测训练价值。[E12][E18][S40][M10][M13][S41]

Insight （为何可解）

一个错误有多值得纠正，至少可能受三个条件影响：模型是否已有理解正确规则的基础、这条错误规则影响多少道不同题、当前更新方式能否真正改变规则的使用。例如，遗漏同一积分公式分母的模型可能只差关键一步；但若连基本运算都不会，直接给公式未必能被吸收。置信度或强烈的“原来我错了”可以作为候选信号，不能直接等于真实学习收益。

Design （如何做）

先用独立前置知识题、同规则变体和稳定性探针，诊断知识准备、规则影响范围与更新兼容性；正确答案与规则由独立验证器核实。然后从相同模型检查点分叉，用相同教师反馈与固定 LoRA/Skill 更新预算纠正不同错误。训练前估计可能的跨题收益，训练后撤掉例题与提示，分别测原题、异结构同规则新题、其他规则和旧能力损失。

确认错误与规则先核实反馈正确
学习前诊断前置知识 / 规则范围
固定预算纠错同教师、同更新器
独立测跨题净收益新题迁移 / 遗忘 / 成本

实验设计 （怎么验证）

构造前置知识高/低 × 错误规则影响范围大/小的配对数学错题，匹配难度、置信度、正确反馈和训练预算；每个候选从同一模型快照独立更新。比较随机、最难优先、高置信度优先、稳定错误优先、Self-Error-Instruct 的 one-shot 信号、LESS 梯度信号、DATAPROPHET 式价值特征、I8 的规则诊断。主指标是训练前预测与真实未见题净增益的对应关系，以及同预算选错题的最终收益；另外报告旧能力退化和诊断成本。如果优势只出现在原题、近似改写，或在匹配知识状态后消失，就不能宣称发现了规则级迁移机制。

正交边界：I8 固定纠错方式，只研究哪个错误规则在当前模型上更有迁移价值；I6 在同题同错误终点比较失败中间过程，I7 只改教学顺序。查看 Hypercorrection 原始证据、最近邻矩阵和完整受控实验 →。目前没有 I8 的实际训练结果。
