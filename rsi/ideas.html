I1：脚手架学习法——哪些该自己学会，哪些用时再查？

采不采得到吸收了会不会丢

一句话：调试思路最好自己掌握，但经常变化的 API 规则可以用时再查。Agent 能自己判断哪些该学会、哪些该留作外部帮助吗？

Challenge （难在哪里）

在帮助下完成任务，不等于撤掉帮助后还能独立做。什么都写进 Skill，可能把过时规则也记住；什么都留在外部，又要反复查询。难的是还不知道未来任务怎么变，就要先决定哪些知识值得长期掌握。

现有工作 （别人研究了什么）

R²Orch 研究的是怎样把 Skill 内化、什么时候可以撤掉 Skill；PATS 研究的是随着学习进展怎样调整并撤除临时支架。我们不是再做一次“帮助逐渐减少”，而是研究不同经验究竟该留在哪里。[S26][S27]

Insight （为何可解）

外部帮助并不都一样。稳定且反复使用的操作方法可能适合自己学会；容易变化的事实可能更适合按需查询。比较撤除帮助后的独立能力、知识变化频率和长期成本，有机会学会这两种方式的取舍。

Design （如何做）

将辅助经验分成稳定方法、易变规则和临时提示，让 Agent 选择内化、外置查询或混合保留。分开测“完全不给帮助”和“允许按需查询”的表现，再根据这些结果更新下一轮的选择方式。

拆分辅助经验稳定方法 / 易变知识
选择存放方式内化 / 查询 / 混合
新任务测能力撤辅与查询分开
更新取舍规则比较收益和成本

实验设计 （怎么验证）

准备稳定的调试技巧与会变动的 API 规则，在相同预算下比较全部内化、全部外置、固定渐隐、自适应取舍，并与 R²Orch/PATS 的可复现做法比较。重点看无辅助的新任务成功率、API 更新后的适应性、调用成本和旧能力退化。如果固定规则同样好，说明动态选择还没有额外价值。

I2：因材施教——同样犯错，为什么学习方法不同？

信号对不对采不采得到

一句话：两个 Agent 都不会修一个 Bug，一个看示范就会了，另一个要比较几次失败才学得会。怎样找到各自最适合的学习方法？

Challenge （难在哪里）

知道“错在哪里”，不等于知道“怎么学最快”。同一种错误，换个模型或学习阶段，最有用的学习方式可能不同；但把所有学法试一遍又太贵。还要避免把眼前这道题的进步当成长久的能力提升。

现有工作 （别人研究了什么）

RSIFlow 研究的是失败后该修改模型、Harness 还是任务产物；MetaSkill-Evolve 研究的是任务 Skill 和改进 Skill 的方法怎样一起演化。我们先固定更新的是 Skill，只研究同样的失败该用哪种学习方法，而不是重新做更新对象路由。[S28][S06]

Insight （为何可解）

只看错误标签，可能看不出 Agent 最适合的学法；但是少量“试学”能告诉我们，它看示范、做反例对照或自己重试后，哪一种真的学得更快。Agent 变强后重新测，就能发现原来有效的方式是否还适合。

Design （如何做）

对同一种失败，从相同 Skill 快照出发，分叉尝试示范、对比失败和独立练习。用另一批任务检验每种方式学完后的独立能力，再选择下一轮学法，并记录它在不同能力阶段的效果。

固定同类失败同一个 Skill 更新目标
小预算试学示范 / 反例 / 重试
测独立进步测试任务不能参与试学
下轮重新选随能力更新学法

实验设计 （怎么验证）

选多个能力阶段的 Agent，在同类任务上比较固定学法、只按错误类型选、普通 bandit、根据少量试学反应选。试学本身的费用也计入预算；主要看未见题的独立提升，以及能力变强后最佳学法是否改变。与 I6 分开：I2 只决定当前学习任务该怎么学，不决定跨多轮要转去补知识还是改验证器。

I3：温故知新——新方法有用，却和旧方法冲突怎么办？

吸收了会不会丢安全

一句话：Agent 学会一个更快的新方法，却把以前在另一种场景下正确的做法弄坏了。新旧本事能不能都留下来？

Challenge （难在哪里）

新 Skill 确实提高了部分任务的成功率，却可能让旧任务变差。直接回滚就失去了新进步；把所有旧题重做一遍又浪费预算。首先得弄清是旧知识真忘了，还是新旧规则用错了地方。

现有工作 （别人研究了什么）

HCL 研究的是 Harness 更新后如何兼顾新任务与旧任务；SkillBoost 研究的是用回归检查和约束防止新 Skill 伤害旧能力。我们进一步研究当新旧方法都各有用处时，怎样通过复习修好冲突，而不是只能拒绝新更新。[S29][S30]

Insight （为何可解）

有些退化未必是忘记，而是两个原本都有效的方法，被用在了不适合的场景。只要找到“什么时候用旧规则、什么时候用新规则”的区别，少量针对这些边界的练习，可能比全部重放旧经验更有效。

Design （如何做）

比较修改前后的失败轨迹，找到出现冲突的条件，自动生成少量只改变一个关键条件的练习。用这些例子修订 Skill 的适用范围或选择规则，必要时再对参数做巩固。最终既要会用新方法，也不能丢旧能力。

发现旧任务退化新旧版本对比
定位冲突条件何时该用哪一条
有针对性地复习只练容易混淆的场景
一起检验新旧能力旧题 / 新题 / 组合题

实验设计 （怎么验证）

准备两套分别有效、合起来容易冲突的 Skill，并加入自然学习中出现的冲突案例。比较退化即回滚、均匀重放、MIR 风格重放、针对冲突条件复习；固定复习次数和记忆预算。分别测旧能力保持、新能力增益、组合任务成功率。如果优势只来自存了更多规则或多练了题，就不能归因于我们的复习方法。[M09]

I4：生产性失败——失败一次就总结，还是再试几次？

信号对不对有没有新东西采不采得到

一句话：API 超时一次，Agent 就总结“这个工具以后别用”，可能学错。什么时候应该继续试，什么时候才值得把经验写进 Skill？

Challenge （难在哪里）

一次失败可能是策略错了，也可能只是网络偶尔超时。太早总结，会把偶然现象当成通用规律；继续试太久，又会浪费探索预算。RSI 不一定有人告诉它正确做法，需要它自己根据执行反馈辨别原因。

现有工作 （别人研究了什么）

ActiveSaddler 研究的是哪些失败模式更值得继续训练；Trace2Skill 研究的是怎样从多条执行轨迹提炼可复用 Skill。我们研究的是面对这一次失败，下一步试什么，什么时候证据够了可以开始总结。[S16][S31]

Insight （为何可解）

不同失败原因，往往会对下一次尝试给出不同预测。一次只改变一个关键条件，就有可能排除错误解释。当继续探索已经很难提供新信息时，再停止并总结经验。关键不是失败越多越好，而是每次尝试能否帮助弄清原因。

Design （如何做）

失败后先列出两三个可能原因，选择最能把它们区分开的安全小实验，例如同样条件重试或只改变一个 API 参数。持续记录支持和反对各原因的证据，足够确定再更新 Skill；证据不够时允许暂不总结。所有试验只在受控环境运行。

列出失败原因策略错 / 工具故障 / 偶发
做辨别性尝试只变一个关键条件
判断何时停止证据是否足够
形成新 Skill再到未见任务复验

实验设计 （怎么验证）

在 API 异常、工具使用和代码执行任务上，比较失败后立即总结、固定重试 N 次、随机补充尝试、针对可能原因选试验并决定停止。匹配 Token、环境调用和总预算，混合可控故障与自然失败。主要比较写入错误规则的比例、未见场景的迁移、单位成本的学习收益；不把“多试几次自然多成功”误当成新机制。整个过程不需要外部教师告诉标准答案。

I5：十模型互教——什么时候交换舞伴，才能一起变强？

有没有新东西采不采得到吸收了会不会丢

一句话：十个能力、专长各异的模型像一个学习班，每轮两两互教、各自更新，再交换搭档。我们想知道什么时候应继续和原伙伴学、什么时候应换人，才能让更多模型长期学到新本领，而不只是一起把眼前的题做对？

Challenge （难在哪里）

一直与同一模型交流，可能反复交换已经掌握的知识；总跟最强模型，又可能难以吸收它的解法，甚至让十个模型越来越相似。更重要的是，组队答对不代表离开伙伴后学会。不同轮次的交换顺序、知识互补和双方收益都可能影响长期增长。

现有工作 （别人研究了什么）

NC 2019《Bridge ties》 研究相同交流次数下，先跨圈还是先组内交流如何改变群体记忆；NC 2026 研究多代人机群体如何通过选择示范者传播新策略。PopuLoRA 已做模型群体出题与共同进化；OPCoD 已做双模型互教；MACE 已做合作伙伴选择；HACE 已做异构模型和 Agent 的相互进化。它们不是空白。[E90][E93][S32][S33][S34][S90]

Insight （为何可解）

一个伙伴的价值，不在于他有多强，而在于双方交流后各自能独立学到多少以前不会的东西。有效的伙伴关系可能随能力和知识变化而变化：需要新方法时跨圈交流，需要消化时保持配对，双方都学不到新东西时再换。Nature 系列关于知识分布、网络结构与收益学习的发现支持研究动机，但未直接验证 LLM 的这种更新。[E91][E92][E94][E95]

Design （如何做）

十个模型分成五对，分别交换验证过的正确和错误轨迹，双方使用相同且固定的更新器更新自己的 LoRA / Skill（首轮只固定一种更新面）。交流后撤除伙伴、清空临时上下文，在未见题上独立测试新能力和旧能力保持，再估计原配对继续交流与换伴的下一轮收益。在十节点伙伴网络里重配五对，而不是固定让最强模型当老师。

十个独立模型不同能力 × 不同专长
五对双向互教同预算、同教学协议
撤伴独立考试双方能力增益与保持
重选伙伴与顺序边际学习收益决定留伴或换伴

实验设计 （怎么验证）

先用 4 模型做全配对的学习收益测量，再扩展到 10 模型，比较固定伙伴、随机轮换、round-robin、固定最强教师、同级配对、跨专长配对、先跨组后巩固、PopuLoRA / MACE 风格匹配、学习收益驱动的动态换伴。各模型交流、参数更新和算力预算匹配，报告个人独立能力、全班净增益、旧能力保持、新解法发现与过早同质化。如果简单轮换已同样有效，就不单独提出复杂路由器。

正交边界：I5 只研究谁和谁学、何时换伴；I2 负责如何教学，I3 负责巩固，I6 研究失败轨迹的学习价值，I7 研究先试还是先学，I8 研究高置信错误的迁移。查看 Nature 证据、完整十模型实验与停止条件 →。教学反馈诊断教师盲点是历史支线，不与 I5 主线混作同一贡献。

I8：Hypercorrection——为什么改正一种错误能学会一类题？

信号对不对吸收了会不会丢

具体问题：同样一道数学错题，一个模型得到正确反馈后只记住答案，另一个却能举一反三。纠正哪种错误值得投入下一轮学习预算？

Observable Phenomenon / Why

Hypercorrection 的人类学习研究发现，高置信度错误经正确反馈后有时更容易被纠正；已有知识可能是重要解释。由此提出待验证的模型假设：前置知识是否充分、错误是否由影响多题的共同规则造成，可能共同决定一次纠错的跨题收益。[E12][E13][E14]

Challenge / Insight / Design

Challenge：置信度不等于学得会；修复原题不等于迁移；真实收益通常要在更新后才能观察。Insight：已有知识准备程度 × 规则影响范围 × 更新兼容性，可能解释实际收益差异。Design：学习前诊断知识与错误模式，固定纠错方式和训练预算，在独立模型副本上检验跨题真实收益。

别人研究的是……；我们研究的是……

Self-Error-Instruct 已按错误类型合成题目，并用 one-shot 示例帮助筛选数据；LESS 已用梯度影响选择训练数据。I8 研究的是当前错误怎样转化为真实持久的跨题学习，以及能否提前预测。[S40][M10]

与 I6 的区别：I8 研究哪些错误规则更有可迁移性；I6 尽量保持错误规则与最终答案一致，单独研究失败过程作为学习材料的作用。
