四项学习功能 · 一条共同主线

03 · 经验获取下一步经历什么，才可能学到有用的东西？识别缺口、构造任务、获得新信息、选择有学习价值的经历。 04 · 学习信号这次经历说明了什么，应该改进哪里？比较反馈可靠性、失败诊断、贡献归因与实际学习收益。 05 · 能力形成怎样把经历变成未来能够使用的能力？连接经验抽象、外部记忆、技能和参数更新。 06 · 学习调控怎样使多次改进相互支持？研究知识冲突、学习顺序、预算分配与学习机制自身的改进。

四项功能共同解释一次经历如何产生变化，以及多次变化怎样累积。它们在实际系统中相互反馈；方法、能力载体、组织方式与来源领域作为描述字段。

必须分开的三个研究主张

主张应观察什么不能据什么下结论
眼前任务做得更好有人帮忙、提示或额外执行后的成功率。当前题目答对，就说自己学会。
Agent 获得了持久能力只保留版本化 Skill / Memory / Harness / 参数，清空临时上下文，在新任务上仍进步。答案、同伴或教师仍在上下文里。
Agent 更会自我改进保留学到的学习策略，重置任务 Agent，在新的任务流中能否更快改进。迭代次数更多、模型更大或训练预算更多。

只要设计了循环，就能叫自我迭代，但要声称“递归地改进改进器”还需要额外证据。如 MetaSkill-Evolve 已研究元技能进化，不能再把“有两个循环”本身作为创新。[S06]

独立评测必须固定并与训练数据隔离；能力提升不会自动扩大 Agent 的真实工具权限。即便改进器学习，安全审计仍应独立。

从教育学概念到论文问题，怎么做？

  1. 先说一个生活中的具体例子。例如为什么新 Skill 影响旧 Skill，或为何同样 Bug 有人看示范就会、有人不会。
  2. 说清最近邻研究了什么。不能因为前人没用“费曼”“温故知新”这些词，就认定没人研究机制。
  3. 问一个更具体的差异。别人研究哪个失败值得修，我们研究失败后下一次试验何时该做、什么时候可以归纳。
  4. 定义 Agent 真的学到了什么。明确 Skill / Memory / Harness / 权重的可持久写入与回滚。
  5. 先做最小对照。同预算比较固定简单策略与我们的方法，排除更多尝试、更多 token、外部答案泄漏。
  6. 再检验长期进步。连续多轮、新任务、旧能力回归，最后才评价改进策略本身有没有变好。
