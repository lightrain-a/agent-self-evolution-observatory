当前研究池：I1–I6 六个问题

我们关心的不只是 Agent 能不能在一次任务里拿到更高分，而是：它能不能通过改写自身 Skill、Memory、Harness 或参数，真正学会下一次如何学得更好？

I1 · 脚手架学习哪些该自己学会，哪些用时再查？ I2 · 因材施教同样犯错，怎么选适合自己的学习方法？ I3 · 温故知新新方法有用却伤了旧能力，怎么办？ I4 · 生产性失败失败一次就总结，还是再试几次？ I5 · 费曼学习法和谁一起学，自己进步最快？ I6 · 瓶颈诊断停止进步后，什么时候该更换学习模式？

I1–I5 各自负责具体学习方式；I6 只负责跨轮判定哪类瓶颈成为主要限制，避免与 I2 的单轮试学选择重复。每个方向都写清最近邻工作、独立实验与停止条件。进入 I1–I5 完整卡片 · 阅读 I6 完整构思 →

例如 R²Orch / PATS 已研究支架撤除；RSIFlow 已选择自改进工作流；HCL / SkillBoost 已研究回归；ActiveSaddler 已选有用的失败；PopuLoRA / OPCoD / MACE 已涉及群体教学、反馈和伙伴探索。我们需要回答比这些工作更细的问题。[S26][S27][S28][S29][S30][S16][S32][S33][S34]

必须分开的三个研究主张

主张应观察什么不能据什么下结论
眼前任务做得更好有人帮忙、提示或额外执行后的成功率。当前题目答对，就说自己学会。
Agent 获得了持久能力只保留版本化 Skill / Memory / Harness / 参数，清空临时上下文，在新任务上仍进步。答案、同伴或教师仍在上下文里。
Agent 更会自我改进保留学到的学习策略，重置任务 Agent，在新的任务流中能否更快改进。迭代次数更多、模型更大或训练预算更多。

只要设计了循环，就能叫自我迭代，但要声称“递归地改进改进器”还需要额外证据。如 MetaSkill-Evolve 已研究元技能进化，不能再把“有两个循环”本身作为创新。[S06]

独立评测必须固定并与训练数据隔离；能力提升不会自动扩大 Agent 的真实工具权限。即便改进器学习，安全审计仍应独立。

从教育学概念到论文问题，怎么做？

  1. 先说一个生活中的具体例子。例如为什么新 Skill 影响旧 Skill，或为何同样 Bug 有人看示范就会、有人不会。
  2. 说清最近邻研究了什么。不能因为前人没用“费曼”“温故知新”这些词，就认定没人研究机制。
  3. 问一个更具体的差异。别人研究哪个失败值得修，我们研究失败后下一次试验何时该做、什么时候可以归纳。
  4. 定义 Agent 真的学到了什么。明确 Skill / Memory / Harness / 权重的可持久写入与回滚。
  5. 先做最小对照。同预算比较固定简单策略与我们的方法，排除更多尝试、更多 token、外部答案泄漏。
  6. 再检验长期进步。连续多轮、新任务、旧能力回归，最后才评价改进策略本身有没有变好。

网站范围、历史方案与证据状态

这是聚焦 RSI 选题的定向研究站，不是穷尽全领域的系统综述。I1–I5 最新描述以 2026-10-27 的问题表述为准：I5 主线为“按自身学习增益动态选择伙伴”；I6 只分析连续学习的瓶颈转移与模式切换，不重复单任务诊断或具体学习算法。

I5 教学反馈诊断作为此前的独立技术支线保留：研究学生的误解能否暴露教师的隐性缺陷。这个实验与“动态伙伴选择”可以共享学生评估基础设施，但不是同一个问题。
