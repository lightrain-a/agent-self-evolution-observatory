Observable Phenomenon｜学会新能力之后，整个系统为什么可能反而变差？

RSI RESEARCH CANDIDATE · UNNUMBERED · 2026-10-28

When should a self-improving agent say “not in my core model, at least not yet”?

一个内容安全 Agent 已经稳定识别旧风险类型。新领域能力可以通过微调获得，但若直接更新共享模型，旧类别的误判也随之上升。即使新任务单独成绩很高，整个系统的净能力也可能下降。若现成外部审核模型或独立 Adapter 已能承接新任务，强迫核心模型马上内化新能力未必最划算。

主科学问题：多轮自我改进中，Agent 能否根据新能力的必要性、旧能力是否仍正确、预期干扰成本和可用外部能力，主动选择内化 / 隔离 / 委托 / 暂缓；并在后续版本更新后重新决定是否内化？

拒绝什么：拒绝一次高风险的内部参数/核心 Skill 接纳，不是拒绝必须执行的任务或安全要求；系统依然可以使用经验证的外置能力。若旧规则已过时，必须允许修订，不能以保护旧能力为理由阻止必要纠正。

与 I3 的关系：I3 研究新能力已写入后，旧能力受损怎样修复；本候选在正式提交更新前做决策。与 I1 的区别：I1 比较知识稳定性、内化与检索位置，本候选必须在知识稳定性与外部查询成本匹配时，通过旧能力冲突风险解释不同的接纳决策。

Why｜同样冲突很大，却不该总是“拒学”

新旧规则的真实关系单看冲突的错误判断合理的待验证行动
A 兼容增长：新能力补足旧能力空白，核心规则都有效把未知当冲突，过度拒绝更新优先内化并验收
B 双方有效但场景不同：新旧规则在各自条件下成立，却会互相干扰一味混合训练或一味保护旧参数隔离 Adapter / 外部专家，保留准确路由与未来重访条件
C 旧规则已失效：新规则才是当前应使用的规范误把旧准确率当作必须保护的能力接受新规则并有条件淘汰旧规则，检查时间/适用范围
D 核心能力应当掌握：高频、低延迟或外部专家不可靠长久外包使核心学习停滞即使内部风险不小，也应考虑更稳健的内部学习与修复

重要洞察：“冲突程度”与“正确的学习接纳行动”不是单调关系。旧规则仍有效吗？外部服务可靠吗？该能力未来调用多少次？其他任务的学习会不会让内化变容易？这些变量共同决定系统级净收益。

人类研究的认知卸载与干扰控制提供动机，不能直接证明 LLM 在拒绝内化后会长期变强；AI 中的 RAG/持续更新在时间知识漂移时也可能错误，因此外部委托不应被当成绝对安全的答案。[E100][M327]

Related Work｜先把持续学习、外部委托和真正 RSI 分三层

研究层级已有论文真正解决什么它没有直接验证什么
固定训练器：Continual LearningEAFT 针对 SFT 高置信度冲突 token 降低梯度；RieSelect 在联邦持续学习中选择风险较低的更新层；CoPE 由 Probe 决定何时增设 VLM 专家。[M320][M321][M322]一次候选新能力可以直接拒绝内部学习、外部专家承接、未来再尝试；元接纳策略在后代任务上变好
可逆/非权重存放ReGrad 用可检索梯度实现临时权重适配；Modular Memory 主张结合参数和上下文学习；Chronos 在时间知识漂移下改进检索的时间一致性。[M323][M326][M327]按照“干扰旧能力—未来内化收益”的反事实证据选择能力承载表面，并提升下一代选择能力
推理时外部委托Learning to Defer 与 Online L2D 决定当前样本交给自身还是可变专家。[M324][M325]是否接纳新技能为长期能力、外包后核心的独立学习、下一代再内化
真正 RSI 邻近RSIFlow 诊断并选择工作流、演化 Meta-Agent；MetaSkill-Evolve 共同演化任务 Skill 与 Meta-Skill；Skill∞ 递归改进并跨任务复用 Meta-Skill。[S28][S06][S320]针对能力冲突，做“拒绝本轮核心更新/外包/暂缓/重访”的跨代学习接纳决策与相应的后续可学习性验证

核心边界：EAFT、RieSelect、CoPE 可以作为某个候选学习动作的固定实现或强基线，但它们不是 RSI 论文。反之，给 EAFT 外围套一层 Meta-Agent、把“新任务扩一个专家”命名为 RSI，也不足以形成贡献。必须用跨代交叉测试证明决策原则本身在变好。

特别区分 CoPE：此处引用的是 CoPE: Continual Probe-guided Expansion for Large Vision-Language Models（ICML 2026），不是同会的同名“Planning and Execution Coordination” Agent 工作。[M322]

Challenge｜学习接纳是比普通任务路由更难的决策

C1 · 不能把梯度冲突直接当旧能力损害

某 token 的低概率和低熵、某层 Fisher 冲突分数，未必对应未见旧任务退化；旧任务有时本来就应该被新规则替代。必须通过相同 checkpoint 的真实小规模更新与冻结回归样本估计。[M320][M321]

C2 · 外包后的成功不等于核心能力增长

独立 Adapter 或外部模型可以立即提高系统成功率，却也可能导致核心模型长期没有学会新技能。需分开测 Core-only 与 System-with-Experts，并计入专家不可用和模型版本变化。

C3 · 未来的学习收益看不见

现在不学，可能避免破坏旧规则；但一直不学，会失去未来降低调用成本的机会。重访条件如果由终测成绩选取，就会产生数据泄漏。要把未见后续学习序列预先冻结，学习收益在事后独立验收。

C4 · 不能把外部接口变成安全绕行

外部模型可能过时、泄露数据、依赖网络，也可能给出无法解释的错误结论；安全关键动作须经过同样的验证和权限隔离，不能因为不是核心参数输出就免除回归门。

Insight｜不是拒绝新知识，而是保留将来再学的选择权

候选机制：对同一个新能力，Agent 不仅比较一次训练后的新旧能力变化，还比较现在内化、隔离承担和未来重访三者的长期净收益。对有效但不兼容的两套能力，暂缓核心更新可能减少不必要的回归；当条件改善时，再尝试内化，有机会把临时外接能力变为自身能力。

需要区分旧规则正确而适用范围不同和旧规则过时。前者可以分叉路由，后者不应因“拒绝遗忘”而永远保存错误。新能力的来源必须经过真实验证，也不因模型自述“冲突很大”就自动判定不可学。

这比静态选择“存记忆还是存参数”更进一步：Agent 学习的是根据新旧冲突的可修复性和未来学习机会，判断什么时候值得改变自身更新表面。任务优化器可以保持固定，元接纳策略必须跨任务、跨版本持续被验证并修订。

Design｜学习接纳的两层进化闭环

冻结候选能力与核心模型版本号、旧规则有效性、训练与专家访问条件
小成本反事实 Probe真实小样本更新、旧能力回归、外部专家可靠性
Admission 选择内化 / 独立隔离 / 外部专家 / 暂缓
接受与版本化保持高优先级约束；记录接纳原因和未来重访条件
后续任务真实验收Core-only / System / 旧能力 / 算力 / 将来还能否学
改进 Meta-Admission Skill使用受控历史结果而非自述，下一代重新判断

候选动作：不是每项新能力都必须修改共享核心

动作执行方式必须满足的约束
Internalize按固定训练器在核心模型或通用 Skill 中真实更新新任务增益真实、旧任务和安全回归达标
Isolate独立 Adapter / 版本化专用 Skill，在路由条件下使用原核心不被污染；组合执行和可用性可复验
Delegate保留核心不变，调用已有且经过验证的外部专家权限、数据、延迟、服务可靠性及服务费用计入总成本
Defer and Revisit本轮不做高风险内化，记录条件和后续触发；必要时由外部服务承担目标能力持续可用；不得永久掩盖重要欠缺

另有一项拒绝无效提案，例如训练材料被证伪或试图绕过安全约束。这与“真实新能力、暂不内化”不是同一决定，不能合并统计。

把当前最优和未来学习潜力分开

AdmissionChoice = argmax expected [System Gain + Future Learnability − Total Cost], subject to Old-Capability & Safety Gates

上述为拟研究的决策原则，不是已经训练出的策略。System Gain 同时测新任务和旧任务；Future Learnability 通过下一批冻结的、未见的新任务需要多少学习预算来衡量；Total Cost 包含所有探测、训练、搜索、外部服务、版本维护与重访。安全硬约束不可由其他任务分数抵消。

两个时间尺度：快环每次决定某项新能力由哪个载体承担；慢环根据真实版本的得失修订 Meta-Admission Skill。慢环可以是版本化 Skill 或经过固定训练程序更新的 LoRA，但必须能被独立重复测试，不能仅指当前 Agent 想到了一个新 Prompt。

P0｜同样有冲突，新能力为什么应该被不同地接纳？

先验证现象，再构建新模块。用可以程序验证的数学规则与代码工具任务，从同一基础模型/Agent 版本构造三种真实关系：A 新旧兼容；B 新旧各自正确但适用条件不同、同时学容易冲突；C 旧规则已过时，需要明确修订。最好再加入 D：外部专家低可靠或高频/低时延要求的能力。固定新能力训练文本、任务调用分布、旧能力优先级、专家可靠性，以及规则有效性标签。

对照可以做什么为什么必须比较
Always-internalize每次普通 SFT/LoRA 内化强制学习导致的旧能力净损失
EAFT / RieSelect（可适配时）仍在既定训练表面内做冲突敏感更新排除“仅降低破坏性梯度即可解决问题”
Always-external / Always-isolated固定调用现成专家或独立模块排除“只要外置就足够”的朴素策略
Fixed conflict threshold只凭梯度冲突或预训练准确率阈值选择判断能否识别 B、C 的不同正确决策
Evidence-based admission相同 probe 预算，比较旧规则有效性、可恢复性及未来净收益验证冲突信息是否提供超出静态路由的价值
Oracle（仅上界）事后看所有分支的真实收益并选择评估策略后悔值；绝不可让策略提前偷看

决定性观察：在稳定性、使用频率、外部服务费等 I1 变量相近时，仅改变新旧规则的有效性和冲突可修复性，最佳接纳方式就会发生可重复反转。如果普通固定存放规则已经一样好，不应再设计复杂 Admission Policy。

验证指标分为Core-only 未见题正确率、System-with-Experts 正确率、旧/新/组合任务保持、安全回归、全部 token / FLOPs / 专家费用及对应的总体效用。外部模型不能因为天然更强且预算不对齐就被宣布为优胜者。对于不可真实重训的 API 闭源模型，外部委托和 Skill 版本轨可测，但参数内化轨需使用可训练的本地模型。

P1｜今天拒绝内化，明天什么时候应该回来学？

只有 P0 证实存在不同的最佳接纳动作，才启动多轮实验。选出 B 类高干扰、但可由外部专家可靠承担的新技能，冻结一条连续任务流；让系统先保持核心不变，记录每次专家调用和误差，再在后续知识/参数变化后考虑重访。

重访策略关键问题
永久外包核心是否永远停滞、长期费用会不会反超？
立即内化后修复是否花费大量预算补救旧能力损失？
固定周期重试是否只是更频繁地训练带来收益？
条件触发重访前置能力、冲突诊断或累计调用成本变化时，是否更适合内化？

预先固定重访触发器，不通过未见终测的答案挑重访时刻。新增能力的监督信息、训练器和更新预算严格匹配，并计入外包阶段的所有成本。关键结果是长期系统净收益、核心独立能力、过早接纳造成的回归、错过可安全内化机会的比率，而不是简单统计委托多少次。

特别注意：如果外部专家始终更可靠而更便宜，选择永久外包也可能是长期最优；不能为证明“RSI 必须内化”强迫模型学习。相反，若新能力是安全必需的核心判断且外包不可靠，则暂缓可能不符合任务合同。

P2｜真正的 RSI：新一代是否更会决定什么值得自己学？

固定任务 Skill 后，交叉比较元策略版本。把通过 P0/P1 获得的、可审计的接纳决策结果作为发展集，改进 Meta-Admission Skill；然后将旧策略 m₀、新策略 m₁、固定规则与通用 RSIFlow / MetaSkill-Evolve / Skill∞ 风格的统一优化器（共享相同候选动作和预算）放入从未用于改进元策略的未来任务族中。

每个分支从完全相同的 Agent、专家服务清单、能力库和训练器快照开始，外部模型身份与费用被冻结。只有元接纳策略不同，后续才允许系统自主决策并形成不同后代。另作冻结任务 Skill 的逐次决策测试，防止“新策略看到了更多新能力”冒充元能力提升。

冻结同一代能力任务 Skill、模型、专家池、预算与验证器
旧/新元规则分别决策Internalize / Isolate / Delegate / Defer
实际执行独立学习安全回归与全成本记录
对未见任务继续迭代观察第 k+1、k+2 代系统
跨代验收新知识掌握、旧能力、决策 regret 与未来学习速度

RSI 成功证据：在同任务、同外部资源、同总预算下，新版元策略更准确地判断何时应内化/暂缓，且最终能以更低的跨轮代价获得更高的持久系统净能力；新元策略优势要在未见冲突类型和后续任务流上保持。

不可省的消融：去掉后续学习收益目标；去掉冲突有效性校验；去掉暂缓/重访；永远固定外部专家；固定元规则仅做更多 Probe；完整上下文历史 vs 净元规则更新。没有这些对照，很容易只验证一个额外提示词或多用了一家强模型。

与 I1 / I3 / RSI 近邻的最终裁决

方向在研究什么判断是否碰撞
I1：内化还是外置相对稳定的知识应保存在哪里，外部调用和内化各有多少成本若新候选只根据频率和存储成本决定外包，直接并入 I1
I3：冲突后修复新能力已被接纳且旧能力受损，怎样定向巩固、修复适用边界若必须先造成损害才能诊断并修复，而事前选择无增量，归入 I3
RSIFlow / MetaSkill-Evolve / Skill∞已能演化改进工作流或 Meta-Skill若只是多一个会选择工具的 Meta-Agent，应归入这些工作；关键是接纳元规则的跨代独立收益
本候选：Learning Admission先判断新能力是否适宜写入核心，暂缓时让外部能力承接、保留未来再内化机会；使这一决策规则逐代改进事前冲突证据 × 决策行为 × 未来可学习性三者共同成立才独立

Go / Merge / Stop

决策预先需要什么证据
GO · 独立成篇P0 出现同等冲突但最佳接纳不同、P1 暂缓/重访有可解释的长期价值、P2 新版元策略在未见任务上显著降低决策 regret 并提高等预算净学习收益
